# Каталог товаров: Next.js + FastAPI + aiogram + PostgreSQL + MinIO

Минимальный сервис каталога:

- администратор добавляет товар в Telegram-боте — одним сообщением «фото + название в подписи»;
- каталог открывается на Next.js в обычном браузере и внутри Telegram Mini App.

Каждый сервис stateless и запускается в нескольких экземплярах (по умолчанию по 2).

## Архитектура

```
Telegram ──webhook──┐                       ┌── web ×2 (Next.js, App Router)
Браузер / Mini App ─┤                       │
                    ▼                       ├── api ×2 (FastAPI) ──┬── PostgreSQL
              nginx (TLS на хосте) ─ nginx ─┤                      └── MinIO (S3)
                                            ├── bot ×2 (aiogram 3) ── Redis
                                            └── /media/* ── MinIO (только чтение)
```

| Сервис | Роль |
|---|---|
| `web` | Страница «Каталог» — серверный компонент, данные берёт из API при каждом запросе. Подключает Telegram WebApp SDK, поэтому та же страница работает как Mini App. |
| `api` | `GET /api/products` — список товаров; `POST /api/products` — создание (только для бота, по внутреннему токену); `GET /api/health`. Слои: роутер → сервис → репозиторий / хранилище. |
| `bot` | Webhook-сервер aiogram. `/start` и любое сообщение — «У меня есть товар» и кнопка Mini App. Администратору — кнопка «Создать товар». |
| `migrate` | Одноразовый запуск `alembic upgrade head` до старта API. |
| `storage-init` | Одноразовая настройка MinIO: бакет с публичным чтением объектов и отдельный пользователь API с правами только на этот бакет. |
| `nginx` | Балансирует запросы по репликам и отдаёт картинки из MinIO по `/media/`. |

## Как обеспечен запуск в нескольких экземплярах

- **Никакого состояния в памяти процесса и на диске.** Товары — в PostgreSQL, изображения — в MinIO, состояние диалога бота (FSM) — в Redis (`RedisStorage`).
- **Бот получает события через webhook, а не polling.** Polling по одному токену может вести только один процесс, а webhook за балансировщиком обслуживают любые реплики.
- **Каждое событие Telegram обрабатывается один раз.** Middleware атомарно захватывает `update_id` в Redis (`SET NX EX 24h`). Если обработка упала, ключ освобождается, и повторная доставка от Telegram обработается заново. Webhook проверяет секретный заголовок `X-Telegram-Bot-Api-Secret-Token`.
- **Создание товара идемпотентно.** Бот передаёт `Idempotency-Key: tg:<chat_id>:<message_id>`. В базе на нём уникальный индекс, поэтому повтор не создаст дубль даже при гонке двух реплик. Если запись в базу не удалась, загруженный файл удаляется из MinIO.
- **Миграции — отдельным шагом,** а не при старте каждой реплики API.
- **Балансировка.** Nginx (≥ 1.27.3, параметр `resolve`) перечитывает DNS Docker и распределяет запросы по всем репликам, включая добавленные через `--scale`.
- **Все реплики бота при старте вызывают `setWebhook`.** Вызов идемпотентный, ограничение частоты от Telegram обрабатывается повтором.

## Безопасность

- Создавать товары может только бот: `POST /api/products` требует `X-Internal-Token` (сравнение через `hmac.compare_digest`). В боте команды добавления доступны только пользователям из `ADMIN_IDS`.
- Тип изображения определяется по сигнатуре файла (JPEG, PNG, WebP), а не по заголовку клиента. Размер ограничен 10 МБ.
- Бакет MinIO открыт только на чтение отдельных объектов, без листинга. API работает под отдельным пользователем MinIO с правами только на свой бакет, а не под root.
- Официальные образы `minio/minio` больше не публикуются, поэтому используется поддерживаемая сборка сообщества `pgsty/minio` с закреплённой версией.
- Название товара экранируется при выводе в боте; на странице React экранирует его сам.
- Контейнеры Python и Node работают не от root.

## Запуск

Нужны Docker с Compose v2 и публичный HTTPS-адрес: без него Telegram не пришлёт события на webhook и не откроет Mini App.

```bash
cp .env.example .env      # заполнить пароли, BOT_TOKEN, ADMIN_IDS, PUBLIC_URL
docker compose up -d --build
docker compose ps         # по 2 контейнера api, bot, web
```

Стенд слушает `127.0.0.1:${HTTP_PORT}` (по умолчанию 8085). TLS завершает nginx на хосте:

```nginx
server {
    server_name catalog.example.com;
    listen 443 ssl;           # сертификат, например, через certbot --nginx

    location / {
        proxy_pass http://127.0.0.1:8085;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Рабочие конфиги стенда https://aisnab.gmcloud.ru — в `deploy/`. Хостер стенда не пускает к Telegram по IPv4, а у контейнеров нет IPv6, поэтому бот ходит в Bot API через nginx хоста (`TELEGRAM_API_BASE=http://host.docker.internal:8086`, `deploy/host-nginx-telegram-relay.conf`): тот подключается по IPv6 и повторяет неудавшиеся подключения. На обычном сервере `TELEGRAM_API_BASE` оставьте пустым.

В @BotFather кнопку Mini App настраивать не обязательно: бот сам ставит кнопку меню «Каталог» на `PUBLIC_URL`.

Масштабирование:

```bash
docker compose up -d --scale api=3 --scale bot=3 --scale web=3
```

## Использование

1. Откройте бота и нажмите `/start` — бот ответит «У меня есть товар» с кнопкой «Открыть каталог».
2. Администратор нажимает «Создать товар» (или `/create`) и отправляет одним сообщением фото с названием в подписи. Отмена — `/cancel`.
3. Товар сразу появляется в каталоге: в Mini App и по адресу `PUBLIC_URL` в браузере.

## Тесты

```bash
docker compose run --rm --no-deps api sh -c "pip install -q -r requirements-dev.txt && python -m pytest -q"
```

Тесты API проверяют: создание и появление товара в каталоге, обязательный внутренний токен, идемпотентность по ключу, отказ для не-изображений, ограничение размера, пустое название, границы `limit`.

## Структура

```
backend/   FastAPI: app/api (роутеры, зависимости), service.py, repository.py, storage.py, migrations/, tests/
bot/       aiogram 3: handlers/, middlewares.py (дедупликация), api_client.py, main.py (webhook-сервер)
web/       Next.js App Router: app/page.tsx (каталог), app/telegram-ready.tsx, lib/products.ts
nginx/     балансировщик и раздача /media/
deploy/    nginx хоста для стенда: TLS-сайт и прокси Bot API
scripts/   smoke-test.sh — проверка поднятого стека (реплики, идемпотентность, медиа, балансировка, отказ реплики)
```

## Что можно развить

- Пагинация каталога по курсору, если товаров станет много.
- Проверка подписи `initData` на сервере, когда в Mini App появятся персональные действия (корзина, заказы).
- Метрики и централизованные логи, readiness-проверки MinIO и Redis.
